# #218 Short observe-only throughput probe v1.0.0

Date: 2026-10-03. This protocol is only for the user-requested short measurement after the reviewed V2 two-group mode is merged. It is not the 15-minute Mainnet canary, H2e/H2c readiness, wallet verification, arming, or a trade. The prior `ced66e7` canary remains FAIL and #215's unknown TradeEvent suffix remains quarantined.

Run two sequential, isolated Mainnet observe-only arms of at most five minutes after health becomes available: V2 executable with the two-group flag OFF, then the **same exact merge SHA** with only that flag ON. Use a fresh disposable PostgreSQL database for each arm, one process and one worker, identical provider, launchpad-only scope, page/cache/coverage/finality settings, the shared ordinary budget enabled at eight physical attempts per rolling second and 64 queued waiters. No signing, submission, wallet loading or executor activation is allowed. If the exact same SHA cannot be used, disclose both SHAs and their diff; do not call the result causal by default.

The private RPC-role harness is a starting point, not executable unchanged: it hardcodes an older SHA, two workers and V1 hydration projection. Rebind it to the exact V2 build and add bounded V2 evidence without leaking RPC URLs, credentials, signatures, mints or raw health. The older scanner-probe harness does not provide sufficient path/dotenv isolation and must not be reused. Before ON, the one-lane arm must actually measure streamed block response sizes and show no response above 32 MiB or unknown size. Otherwise leave V2 OFF and report the capacity experiment INCONCLUSIVE.

Capture closed, aggregate-only samples at T0, T+2, T+5 and STOPPED, with bounded interim aggregates every 15 seconds: incoming and durably classified signatures per second, source/result/commitment and block-size mix, pending/claimable backlog and oldest age, catch-up frontier, source/admission/RPC/snapshot phase latencies, physical attempts/429 by role, budget queue/rejections, groups/fetches/bodies/bytes and RSS high-water, finality, duplicate/terminal counts and cleanup. The durable classification count, not cache locates or grants, is the throughput numerator. The same populations and clock definitions must be used in both arms.

This is a diagnostic comparison, not a pass/fail replacement for the existing canary. Treat workload comparability as INCONCLUSIVE if arrival rates differ by more than 10%, principal source/result/commitment proportions by more than five percentage points, or block sizes materially differ. Under comparable loads, report an observed useful gain only if T+2→T+5 durable classifications per second improve by at least 20%, arrival-adjusted pending slope decreases, and oldest age and observed p95 do not deteriorate. Confirm that two distinct block groups actually overlap. Report terminal and censored populations alongside p95; a small eligible subset cannot prove end-to-end timeliness.

Safety conditions for either arm: zero HTTP 429, local budget rejection, oversized response, provider/finality/idempotence contradiction or silent dropped record; exact group/budget/memory bounds; no unresolved operation at STOPPED. Monitor free bytes on the repository and task-owned temporary volume before start and every ten seconds. At or below 5,000,000,000 bytes, stop producers, clean only identified task-owned regenerateable artifacts, remeasure, and continue only above the threshold. Keep private files mode 0600 under a 0700 directory for at most four hours, then securely discard task-owned raw material; keep only expurgated aggregate conclusions. Use bounded SIGTERM shutdown (45 seconds); SIGKILL or unresolved cleanup makes the measurement incomplete.

Two different live windows cannot alone establish strict causality even if their mix is similar. To use the word **causal**, replay the same ordered, sanitized workload and the same bounded response fixtures against fresh offline states in V1/OFF and V2/ON, with no additional RPC, and prove the same classification outputs/frontier plus a faster completion time. Without that controlled replay, label the result **observed gain under comparable live mix**. After publishing the redacted short-probe report, STOP. Set `canaryVerdict=NOT_EVALUATED`; do not schedule the 15-minute canary or any later gate in this task.
