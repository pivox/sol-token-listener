# #218 Two-group hydration evidence design v1.1.1

Date: 2026-10-03. Parent: [classification throughput capacity design](2026-10-03-classification-throughput-capacity-design.md). This is an observe-only, default-OFF capacity experiment. It does not authorize a wallet, transaction submission, H2e readiness or acceptance of the unknown Pump.fun TradeEvent tail (#215).

## Decision and boundaries

Use a separate V2 contract, not a silent extension of the exact V1 heartbeat. V1 means one admitted hydration group and remains the default. V2 is restart-only and requires `EXECUTION_MODE=observe`, launchpad-only ingestion, one worker, and the shared ordinary HTTP attempt budget enabled. All invalid combinations fail before listener startup. The user-approved local policy is nominal 10 RPC/s, 2 RPC/s unborrowable for a future exit, and no more than 8 physical ordinary attempts in any rolling second. This is a local envelope, not a provider-wide rate-limit attestation. No `sendTransaction` path is part of V2.

The alternative of increasing only the cache concurrency is rejected: the group admission controller still permits one distinct group, the classifier waits on slot order, and the 19-gate canary currently rejects concurrency above one. An alternative source that supplies authoritative transaction identity without fetching blocks remains possible later, but no such source has been validated. Two groups under the budget is the smallest measurable candidate.

## Admission and ordering

A group identity is `(route epoch, provider ID, slot, effective commitment)`. Two callers for the same identity join one group and one physical fetch. `CONFIRMED` and `FINALIZED` are distinct. At most two distinct groups or unbound worker reservations may occupy admission in total; a same-group join consumes no new group. Pending groups and callers have explicit finite caps and abortable waits. A worker/classifier contest alternates grants so neither can starve; a worker may not bypass a previously queued classifier group indefinitely.

The classifier may hydrate a second slot before the first finishes, but its durable classification receipts are written in original source order. A later slot cannot advance a checkpoint while an earlier slot is unresolved. Failed/aborted earlier work prevents later write-through. On restart, the existing idempotent receipts and durable frontier determine replay; no volatile V2 result is assumed persisted. Provider switch or route-epoch change invalidates future cache reuse. A started operation occupies a group and memory capacity until it actually settles, even if one caller cancels or cache entries are cleared. The physical request aborts only when its last consumer leaves. Shutdown rejects pending admissions, aborts started work, waits for settlement, and records no active/queued work in the final heartbeat.

## Memory and RPC boundaries

The existing retained-entry limit of 8 MiB does not bound raw `getBlock` HTTP bodies or SDK JSON parsing. Before V2 can be enabled, the block fetch path must enforce a 32 MiB per-response streaming byte ceiling and a 64 MiB combined two-response in-flight ceiling, with counters for rejected oversized bodies. This matches the existing 32 MiB maximum compression input; it is a fail-closed experimental ceiling, not proof that every Mainnet block fits. `Content-Length` is advisory: actual streamed bytes are counted and overflow cancels the body. No partial response can yield a transaction, receipt or checkpoint. A bounded one-lane size probe must show the rejection rate before V2 activation; if legitimate blocks exceed the ceiling, V2 remains OFF until a separately versioned memory policy is approved. The V2 probe must also report RSS at the existing canary boundaries and high-water memory during response handling.

All source, finality, block, worker/health shared-client calls and failover retries spend from the same 8-attempt rolling-second budget. Queue saturation or closure is a local admission outcome, never evidence that a particular provider failed; it cannot rotate the provider or degrade an otherwise healthy WebSocket session. A real network/HTTP failure keeps existing failover behavior. A local budget rejection records no physical attempt or 429. The budget queue is bounded at 64 and its wait time counts toward request deadlines.

## Versioned evidence

The V1 heartbeat, API and `mainnet-observe-canary-input.v1` exact shapes remain unchanged and continue to reject a two-group claim. V2 uses explicit discriminants (`version: 2`, `configuredGroups: 2`) for `blockHydration` and `blockHydrationAdmission`. In addition to V1's common counters, V2 reports actual/maximum active groups, queued groups, unbound reservations, physical block fetches in flight, same-group joins, per-role grants and waits, cancellation and shutdown settlement. A separate `ordinaryRpcBudget` V2 snapshot reports configured 8 attempts/rolling second, current and maximum rolling starts, queued/current/maximum waiters, local rejections and closed state. Memory evidence reports current/maximum streamed bytes and oversized responses. Counts are bounded non-negative safe integers; clocks are monotonic; identities, URLs, bodies, signatures, mints and keys are omitted. Missing, overflowing, malformed or contradictory metrics cannot be interpreted as zero.

PostgreSQL continues to store the immutable heartbeat JSONB; write-side validation accepts only exact V1 or exact V2 shapes. The public `/api/v1/health` projection returns the discriminated form and rejects malformed stored V2 instead of projecting V1. No destructive migration is needed. The separate frontend remains a consumer; the diagnostic HTML is not the product contract.

The private canary input version is `mainnet-observe-canary-input.v2`, selected explicitly by its parser. It carries exact V2 snapshots at T0, T+5, T+15, FINAL_PRESTOP and STOPPED; mixing V1/V2 within a run is invalid. Its evaluator reuses the same 19 safety gates and thresholds, with V2-aware hydration/admission validation and an additional local budget/memory gate. It requires zero observed HTTP 429, no local budget rejection, no provider mixing, no cross-finality reuse, no stale classification, bounded backlog/p95/RSS and zero in-flight/queued work at STOPPED. Failure precedence remains `FAIL` over `INCONCLUSIVE` over `PASS`. V1 golden fixtures and results cannot change. A V2 observe-only PASS is not H2e project capacity proof and does not open the wallet gate.

### Closed V2 field manifests

The following names, types and bounds are the V2 contract; all objects have exact own data properties, no accessors/proxies, and are copied/frozen before persistence. Unless stated otherwise, counters are non-negative safe integers, and `current <= maximum` is required.

`blockHydration` retains the V1 common counters `locates`, `hits`, `misses`, `inFlightJoins`, `fetches`, `forcedRefreshes`, `evictions`, `oversizeBypasses`, `fetchFailures`, `epochInvalidations`, `retainedEntries`, `retainedBytes`, `inFlightFetches`, `queuedFetches`, and the exact `queueDelayMs: {last, maximum}` pair. V2 replaces the V1 identity with `version: 2`, `enabled: true`, `configuredGroups: 2`; its additional fields are `activeGroups`, `maximumActiveGroups`, `queuedGroups`, `maximumQueuedGroups`, `maximumInFlightFetches`, `maximumQueuedFetches`, `sameGroupJoins`, `unsettledAfterCancel`, and `maximumUnsettledAfterCancel`. Active groups and in-flight fetches are each at most two. Queued groups are at most two; the entire caller wait queue is at most 1,024, preserving the existing bound. `retainedEntries <= 64`, `retainedBytes <= 67,108,864`, and `queueDelayMs.last <= queueDelayMs.maximum` when both are present. STOPPED requires all current group/fetch/queue/unsettled fields to be zero.

`blockHydrationAdmission` has exact fields `version: 2`, `enabled: true`, `configuredGroups: 2`, `registeredWorkers`, `pendingWorkers`, `maximumPendingWorkers`, `pendingClassifierGroups`, `maximumPendingClassifierGroups`, `unboundReservations`, `activeGroups`, `maximumAdmitted`, `worker`, and `classifier`. The role objects retain exact V1 fields `grants`, `cancellations`, `oldestWaitMs`, `lastWaitMs`, `maximumWaitMs`. `registeredWorkers <= 1` (one while RUNNING), `pendingWorkers <= 1`, `pendingClassifierGroups <= 2`, `unboundReservations + activeGroups <= 2`, `maximumAdmitted <= 2`; all current counts must be zero at STOPPED except `registeredWorkers`, which may be zero or one according to the shutdown order. Admission waiters and cache-queued fetches are different populations: no equality between their counters is asserted at snapshot time.

`ordinaryRpcBudget` has exact fields `version: 2`, `enabled: true`, `windowMs: 1000`, `maxAttemptsPerWindow: 8`, `maxWaiters: 64`, `startsInWindow`, `maximumStartsInWindow`, `queuedWaiters`, `maximumQueuedWaiters`, `localRejections`, and `closed`. `startsInWindow` and its maximum are at most eight; queue and its maximum are at most 64. `localRejections` must remain zero for a V2 canary PASS. At STOPPED, `queuedWaiters=0` and `closed=true`; the historical maximum remains observable.

`blockResponseMemory` has exact fields `version: 2`, `perResponseLimitBytes: 33,554,432`, `totalInFlightLimitBytes: 67,108,864`, `activeBodies`, `inFlightBytes`, `maximumInFlightBytes`, `oversizedResponses`, and `maximumRssBytes`. `activeBodies <= 2`, `inFlightBytes <= maximumInFlightBytes <= 67,108,864`, and `maximumRssBytes` is a monotonic sampled process high-water mark taken during response streaming and parsing. STOPPED requires `activeBodies=0` and `inFlightBytes=0`. A positive `oversizedResponses` keeps the throughput/compatibility claim INCONCLUSIVE even when memory stayed bounded; it is not silently treated as a successfully decoded block.

The V2 canary result is `mainnet-observe-canary-result.v2` with the existing nineteen gate names unchanged plus `capacityEnvelope`. The new gate requires all four V2 sidecars at all five boundaries, coherent maxima and counters, unchanged provider membership and the stopped drain conditions above. Existing `http429`, `rss`, backlog, finality, terminal and cleanup gates keep their V1 thresholds. V2 never projects its measurements into a forged V1 `callerConcurrency: 1` object. The `capacityEnvelope` gate is INCONCLUSIVE on missing evidence or positive `oversizedResponses`; it is FAIL on malformed/contradictory evidence, exceeded bounds or a positive `localRejections` count. No full canary is authorized by this design task; only its pure contract may be delivered before the short observe-only throughput probe.

## Verification and rollout

RED/GREEN tests cover exact V1 preservation, config fail-closed, two distinct groups/third waiting, same-key join, worker fairness, A→B→A route epochs, commitment/finality separation, out-of-order completion with ordered writes, restart/idempotence, last-consumer abort, budget queue cancellation, late settlement, body overflow/chunked responses, bounded counters/RSS, malformed V2 projection and all old canary gates. Unit/integration tests precede one external review cycle and CI green.

A short observe-only Mainnet probe compares exact one-lane and two-lane commits under comparable arrival mix. It records physical attempts, 429, backlog slope, age, p95, finality, response-size and RSS high-water, not merely fetch latency. A causal gain with no 429 and bounded memory is necessary before the exact-merge 15-minute canary. The original failed canary remains FAIL. Three/four groups need a separately versioned, operator-approved amendment. The unknown 24-byte Pump.fun TradeEvent profile stays quarantined until official or independently validated on-chain serialization evidence exists; #218 cannot claim a full canary PASS while #215's decoder gate fails.
